- Nothing changes for an app that only bumps its pin, and nothing needs regenerating.
- **Generated first Store screenshot (D-123):** `devkit-store-hero` draws a listing's first screenshot in every listing locale, in the split layout (brand panel and headline beside the app's real window or flyout, enlarged) or the brand card (icon, name, headline and subline over the brand gradient, with the window optionally faded behind). Add a `hero` block to the first entry of a store's list in `store-assets/manifest.json` and a `heroHeadline` (and `heroSubline`) to each locale in `listings.json`, then run `devkit-store-hero`; add `devkit-store-hero --check` to `validate`. See "Store heroes" in the README.
- **A tall flyout can be cut at the bottom:** with `"fade": "bottom"`, a split hero's `crop` may cut the window's bottom edge, and the UI fades out toward the cut. Every other cut is refused.
- **Fonts download once:** the first run downloads its pinned fonts (about 27 MB) into `~/.cache/devkit/fonts`. In CI, cache that folder, or set `DEVKIT_FONTS_DIR`, and fill it with `devkit-store-hero --fetch-fonts`.
- **Run `--check` on Linux x64 for now:** the feature's commit message says the same inputs give the same pixels on every machine. So far that is shown only on Linux x64 (WSL and CI), so run `--check` there, as `devkit-notices --check` already asks. Japanese and Chinese line breaks follow the ICU data in Node, so a Node update can move one; `--check` then names the hero and a plain run redraws it.
- **Coming from v0.20.3 (winui-app-kit's pin):** nothing in v0.21.0 to v0.26.0 needs an edit in a Windows app. The Play icon move (v0.21.0) affects Android targets only, the icon options added since are opt-in, and the notices and deploy changes do not touch the kit's commands.
