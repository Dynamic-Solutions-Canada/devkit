- Test two branches together: `devkit use <dependency> <worktree>` points one checkout's declared dependency at a running linked worktree of the other project, and `devkit use <dependency> --primary` points it back. The choice is per checkout, kept outside both repositories, and applies from the next dev start; `devkit use` on its own lists each dependency and its health. A damaged or out-of-date choice stops startup instead of silently using the primary checkout, and `devkit cleanup --yes` removes it with the worktree.
- `env()` now receives `proxyAddress`, and every project gets `DEVKIT_PROXY_ADDRESS`: the address a container should map dependency hostnames to in Compose `extra_hosts`. If your app works this out from devkit's machine settings, or hard-codes `host-gateway`, replace that with `"<hostname>:${DEVKIT_PROXY_ADDRESS}"`. It fixes containers that could not reach another devkit project when the proxy uses host networking.
- devkit now requires Node 22.12 or later, below 25. Apps on Node 22 or 24 need no change; an app still on Node 20 must move first, because `engine-strict=true` refuses the install.
- devkit is MIT licensed, with a `LICENSE` file in the package.
- The README is now the one usage guide every app links to, including a self-contained "Remote development and an existing nginx server" section. Apps can delete their own copies of devkit's remote-development and cleanup instructions and link to it instead.
