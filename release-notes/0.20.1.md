- The generated deploy script could skip the database backup on the first deploy after a compose file rename: it looked for the database through the new file, which was not on the server yet, and a hidden error read as "nothing to back up". It now finds the running database by its Compose labels (the service name and the checkout's folder), so the lookup works before and after a rename or a new `name:`, and any docker error in the backup step stops the deploy. Only no matching container counts as a first deploy, and two matches are refused. Run `npm exec devkit-init` and commit the updated script before your next deploy.
- The generated deploy script now brings submodules to their pinned commits after updating the server checkout, before the stack is rebuilt. Before, a submodule pin bump deployed the old submodule, and a fresh server checkout had none, so a production build that imports one failed. It runs only when the repo has a `.gitmodules`; set `deploy.submodules: false` in `devkit.config.mjs` to skip it. Run `npm exec devkit-init` and commit the updated script.
- New `deploy.versionFrom`: the `package.json` whose `version` labels the deployed image, for apps whose product version lives in a workspace. The default is still the root `package.json`.
