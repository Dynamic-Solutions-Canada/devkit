- **The Play icon moves to `store-assets/play/graphics/icon.png`**, out of the folder that holds the phone screenshots, so publishing and screenshot tools no longer pick it up as a screenshot. Set `playPath` in the Android target to put it elsewhere. Run `devkit-icons`, then `git rm store-assets/play/icon.png`: `devkit-icons --check` fails while the old file is still there.
- **`devkit-icons` finds Android icons that hide the generated ones.** Capacitor's template ships `drawable-v24/ic_launcher_foreground.xml`, which wins over devkit's icon on every device when `minSdk` is 24 or higher, so the app could ship the template's robot icon while `--check` passed. `devkit-icons` now names every same-named launcher, foreground, background, monochrome or notification icon in `res/` that it did not write, and `--check` fails until they are removed. It never deletes them itself. Remove the listed files with `git rm`. With `legacy` off it also lists the template's launcher PNGs: if your `minSdk` is below 26, set `legacy` to true instead of deleting them, since Android 7 needs them. The check reads only the configured `res` folder, so an app that overlays icons onto a generated, untracked Android project still deletes the stale files in its own setup script.
- **The iPhone and Play icons can use the maskable master.** Set `"appleTouchMaster": "maskable"` in the web target or `"playMaster": "maskable"` in the Android target to draw that icon from `icon-maskable.svg` instead of `icon.svg`. Both still sit on `background`. The default stays `"icon"`, so nothing changes until you opt in.
- **`npm run dev -- --fresh` resets the database without Prisma's reset commands.** Prisma 7 refuses `db push --force-reset` and `migrate reset` when an AI agent runs them. devkit now drops this worktree's database and recreates it empty before `dev:container` starts, so the fresh path there can be `prisma migrate deploy` plus your seed. `--fresh` now refuses the primary checkout, as `devkit reset` does, because that database is your real dev data. Reset it yourself with your app's own tooling, for example `prisma migrate reset`. The generated dev runner is unchanged, so this needs no `devkit-init` run.
